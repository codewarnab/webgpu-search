🔬 Key Architectural Takeaways Crossover Reality
1. Retained VRAM vs Cold Upload Uploading 1M rows over PCIe takes ~8–20ms. If data is re-uploaded every keystroke, CPU always wins. But when data is retained in GPU VRAM (loaded once), keystroke search only sends a 272-byte uniform, unlocking pure GPU compute speed.
2. The mapAsync() Fixed Latency Floor WebGPU buffer mapping has a fixed ~1ms to 3ms round-trip overhead. Below 50k items, uFuzzy executes in <1ms on CPU, making CPU 4× faster at small scale. Above 100k–2M items, CPU slows down to 17–160ms+, while GPU compute stays near flat.
3. Candidate Pool Compaction & CPU Ranking Instead of transferring all 2,000,000 rows, the compute shader writes up to 8,192 scored candidates into a compact 64 KB buffer. The CPU then sorts candidates by score to return the top 1,000, eliminating PCIe readback bottleneck while avoiding premature match dropping.

Warp Divergence in WGSL

Variable-length string matching creates warp divergence across SIMD lanes. However, bounding strings to fixed slots (64 bytes) caps thread branch depth to 60 iterations, enabling massive parallel throughput despite divergence.

Where the Crossover Sits

At N < 50,000, CPU uFuzzy is faster (<1ms) than WebGPU's async mapAsync round-trip (~3ms). Between 50,000 and 100,000 rows, WebGPU crosses over and takes the lead. At 2M rows, GPU is ~9× to 20× faster.
